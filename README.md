# V7 大论文逻辑版（预上线）

> **论文**：基于 SM9 与生物特征的零信任 P2P 网络安全机制研究
>
> 本仓库是大论文的「受控实验工程」主仓库：三方向代码、实验、结果数据、论文证据统一管理，遵循「每实验独立存储 + Git 云端同步」规范。

## 一、三方向概述

| 方向 | 定位 | 内容 | 关键机制 |
|---|---|---|---|
| 方向一 | 核心创新 | SM9 + 生物特征模糊提取的 Kerberos 身份认证 | 生物 DID + 非存储式模板 + 前置验签 + 安全熔断 |
| 方向二 | 机制递进 | 基于 ST 票据的 P2P VPN 安全通信 | 设备 DID + ST 准入 + 代理授权 + 流量整形 |
| 方向三 | 应用验证 | 面向 MCP 云服务的访问控制 | 双 DID + 双 ST + 双签名链 + 四步验证 |

统一语义：**DID = 身份标识，ST = 授权票据，ticket_id = 审计关联键**。

## 四、数据同步规范（重要）

> 结果数据是论文核心资产，必须纳入 Git 云端同步，防止本地丢失。

1. **结果 CSV 必须提交**：每实验 `结果/` 目录下的 CSV 全部纳入 git 跟踪，不忽略。
2. **每实验完成后立即同步**：跑完一个实验 → 检查 `结果/` 有新数据 → `git add` + `git commit` + `git push`。
3. **不提交的内容**（已在 .gitignore）：`__pycache__/`、`.pytest_cache/`、`cache/`（特征缓存大文件）、`*.npy`、`*.onnx`、模型文件。
4. **严禁提交**：密钥、真实生物特征原图、Access Token、密码、私钥、环境变量。
5. **固定种子可复现**：SEED=20260817，同一脚本可复现同一结果。

## 五、Git 规范

- 本地是主实验环境，GitHub 为远端同步仓库。
- 建议分支：`main` + 每实验一个 `exp/xxx` 分支，一个实验 = 一组 commit。
- 每任务提交独立 commit，先验证再提交。
- 禁止：force push、reset --hard、覆盖远端历史、删除旧实验结果。
